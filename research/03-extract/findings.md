# The weighted ATUS extract — build and proof

Ticket 03 · built and verified 2026-08-09 · claude (opus)

Builds on the ticket-02 provenance record ([`../02-atus-source/findings.md`](../02-atus-source/findings.md)).
Decisions **S1–S5** and **S10** were the build contract; none was re-decided here.

**The gate is passed.** 637 of 639 published BLS Table A-1 cells reproduce exactly, across 2019,
2023 and 2024, for total / men / women, on all three published statistics. The two that do not are
documented below; both are smaller than the last digit BLS prints.

## Where it lives, and how to rebuild it

| | |
|---|---|
| Pipeline | [`scripts/`](../../scripts) — `atus/` (manifest, reader, category map, estimators, published targets) plus three entry points |
| Rebuild | `npm run data` — fetch → build → verify. Roughly 90 s cold. |
| Raw files | `data/raw/` — gitignored, re-fetched and hash-verified on every run |
| Extract | `data/extract/` — gitignored, ~25 MB, regenerated by `npm run data:build` |
| Gate detail | [`gate-table.md`](gate-table.md) — every one of the 639 published cells vs computed |

The extract is **two files per year**, joined on `TUCASEID`, rather than one denormalized table. The
episode stream is 476k rows; carrying 26 demographic columns on each of them would quadruple the
payload to say nothing new. Downstream code joins in one line.

**`episodes-<year>.csv`** — one row per respondent-day per activity episode:

`TUCASEID · N · START_MIN_FROM_4AM · DUR_MIN · TRCODE · TEWHERE · MAJOR`

`START_MIN_FROM_4AM` is minutes since the 4:00 a.m. diary-day origin, 0–1439 (S2), so episode 1 of
every day starts at 0 and each day's durations chain to exactly 1440. Clock time is
`(START_MIN_FROM_4AM + 240) mod 1440`. `DUR_MIN` is `TUACTDUR24`, never `TUACTDUR`. `MAJOR` is the
published BLS category (see below). `TEWHERE` keeps its sentinels — **−1 is out of universe, not a
location** (S10).

**`respondents-<year>.csv`** — one row per respondent-day:

`TUCASEID · TUFINLWGT · TUYEAR · TUMONTH · TUDIARYDATE · TUDIARYDAY · TRHOLIDAY · TELFS · TRDPFTPT ·
TEHRUSLT · TRCHILDNUM · TRHHCHILD · TRYHHCHILD · TRSPPRES · TESPEMPNOT · TEMJOT · TESCHENR · TEAGE ·
TESEX · PEEDUCA · PTDTRACE · PEHSPNON · GTMETSTA · WORK_MIN · COMMUTE_MIN · WORK_AT_HOME_MIN`

Everything through `TESCHENR` comes from the Respondent file. **Age, sex, race, ethnicity, education
and metro status come from the Activity Summary file** — they are on no other file this project
downloads (the Respondent file carries no `TEAGE`, no `TESEX`, and no `G`-prefixed variable at all).
Only these fixed-name demographic columns are read from it; its `t######` minute columns, the
year-specific trap S1 rules out, are never used for a measure. The last three columns are derived
from the episode stream, because telework and commuting exist nowhere else: work = tier 1 `05`,
commute = tier 2 `1805`, work-at-home = work episodes with `TEWHERE = 1`.

Filter choices stay on ATUS-side variables, so none of the ticket-02 redefinition traps (industry,
occupation, earnings topcodes, CPS parent linkage) apply.

## Acquisition — the pinned hashes still hold

All nine ZIPs (Respondent, Activity, Activity Summary × 2019, 2023, 2024) re-fetched 2026-08-09 and
compared to the ticket-02 record: **byte size and SHA-256 identical on all nine.** BLS has not
silently re-released any of them since 2026-08-08. `scripts/fetch-atus.ts` aborts on any mismatch
rather than continuing with different bytes.

One acquisition detail worth keeping: bls.gov 403s a bare `curl`, and the discriminating header is
**`Accept-Encoding`** — a browser User-Agent alone is not enough. The full header set is in
`scripts/atus/manifest.ts`.

## The invariants BLS only asserts — all verified in the bytes

Every check below runs on every build and aborts the pipeline on failure. All pass for all three
years.

| Check | Result |
|---|---|
| `TUCASEID` unique on the Respondent file | pass — 9,435 / 8,548 / 7,669 rows, all distinct |
| `TUCASEID` unique on the Activity Summary file | pass |
| Respondent, Summary and Activity files cover the same respondents | pass, exactly |
| `TUACTIVITY_N` runs 1…n with no gaps inside a diary day | pass |
| **Every respondent-day's `TUACTDUR24` sums to exactly 1440** | pass — 0 days off, all years |
| Episode start times chain contiguously from the 4:00 a.m. origin | pass — 0 episodes off |
| Running duration equals `TUCUMDUR24` at every episode | pass |
| start + `TUACTDUR24` = `TUSTOPTIME` on every untruncated episode | pass |
| `TUACTDUR24` an integer in 1…1440; `TRCODE` a 6-digit code | pass |
| Every activity code maps to a published BLS category | pass |
| **Per-respondent minutes per 6-digit code = the Activity Summary file** | pass — 0 cells differ, out of 386 × 9,435 + 374 × 8,548 + 372 × 7,669 ≈ 8.5 M comparisons |

That last one is the strongest single check in the build: BLS's own pre-summed file is an
independent computation of the same quantity, and this pipeline agrees with it on every cell.

**The harness was proven able to fail**, not merely observed passing. Swapping `TUACTDUR24` for
`TUACTDUR` turns the 1440 check red (8,768 bad days in 2019 alone) and the Summary cross-check red;
mis-filing one travel code turns 50 gate cells red. Both perturbations were run and reverted.

### Weights (S3)

| Year | Σ `TUFINLWGT` (person-days) | ÷ *D* → people | Weighted weekend share | Unweighted |
|---|---:|---:|---:|---:|
| 2019 | 96,127,263,296 | 263.4 M | 28.49 % | 50.80 % |
| 2023 | 99,037,971,127 | 271.3 M | 28.77 % | 48.92 % |
| 2024 | 99,885,968,916 | 272.9 M | 28.41 % | 49.97 % |

*D* = 365 / 365 / **366** (S4). The population column is the civilian noninstitutional population
aged 15+ in households, 50 states + DC (S9) — the right order of magnitude, and rising as expected.

The weekend columns are the concrete size of the bias S3 warns about: **half the sample is a weekend
day, and the weighted truth is two-sevenths.** An unweighted "average day" would be roughly 1.8×
over-weighted toward Saturday and Sunday. Confirmed at 2/7 ± 0.3 pp for all three years.

### Sentinels and uncodeable time (S10)

| Year | `TEWHERE` = −1 (out of universe) | −2 | −3 | `50xxxx` uncodeable |
|---|---:|---:|---:|---:|
| 2019 | 35,127 of 182,980 episodes | 0 | 1 | 1.00 % of all minutes |
| 2023 | 30,180 of 153,120 | 0 | 3 | 0.74 % |
| 2024 | 27,231 of 139,535 | 0 | 0 | 0.71 % |

Roughly one episode in five has no location, by design — including sleep, the largest block of the
day. Any location view must treat −1 as a category or an explicit exclusion, never as missing.
Uncodeable time is kept: dropping it would break the 1440-minute day.

## The gate: BLS Table A-1, reproduced

Target: **Table A-1, "Time spent in detailed primary activities and percent of the civilian
population engaging in each activity, averages per day by sex"** —
[2019](https://www.bls.gov/tus/tables/a1-2019.pdf) ·
[2023](https://www.bls.gov/tus/tables/a1-2023.pdf) ·
[2024](https://www.bls.gov/tus/tables/a1-2024.pdf). (There is no 2020 table — BLS does not publish
annual 2020 estimates, which is S6 seen from the other side.)

Every published cell is compared at the precision BLS prints: two decimals for hours, one for
percents. 24 activity rows × 3 statistics × 3 sex slices × 3 years, minus the cells BLS marks
"approximately zero" or suppresses.

| Year | Cells reproduced |
|---|---|
| 2019 | 212 / 213 |
| 2023 | **213 / 213** |
| 2024 | 212 / 213 |
| **Total** | **637 / 639** |

Reproduced exactly, every cell, every year, every sex, all three statistics: *Total all activities ·
Personal care · Sleeping · Grooming · Eating and drinking (and its non-travel line) · Household
activities · Travel related to household activities · Purchasing goods and services · Caring for and
helping household members · Caring for and helping nonhousehold members · Working and work-related
activities · Working · Travel related to work · Educational activities · Organizational, civic, and
religious activities · Leisure and sports · Socializing, relaxing, and leisure · Relaxing and leisure
· Watching TV · Sports, exercise, and recreation · Telephone calls, mail, and e-mail · Other
activities, not elsewhere classified.*

The four §7.4 estimators are used verbatim: average hours per day = Σ(w·T)/Σw · participation rate =
Σ(w·I)/Σw · average hours among participants = Σ(w·I·T)/Σ(w·I) · participants = Σ(w·I)/*D*.

### The two cells that do not reproduce

| Year | Cell | BLS | Computed | Gap |
|---|---|---:|---:|---|
| 2019 | Socializing and communicating · % engaged · women | 37.0 | 36.9128 | 0.09 pp (~3 respondents) |
| 2024 | Socializing and communicating · hours/participant · women | 1.96 | 1.9540 | 0.006 h (22 seconds) |

Both are in the women slice of one leaf whose other 25 cells reproduce exactly. The definition is
not the cause: `1201 + 1202` is right, and every alternative tried — adding `1205` (waiting
associated with socializing), `1204`, `1299` — breaks cells that currently pass. They are recorded
rather than fitted away, and pinned in `scripts/verify-extract.ts` so that a *real* regression at
these cells still fails the gate.

## What was learned about BLS's published categories

BLS's twelve published major categories are **not** raw tier-1 codes, and the mapping is not stated
in any ATUS document read in ticket 02 or this one. It was recovered from the arithmetic of Table
A-1 — each major line equals the sum of its own printed sub-lines — and then confirmed against 639
cells. Three conventions:

1. **Travel is redistributed.** Tier 1 = `18` (Traveling) is not a category. Each `18xx` tier 2 is
   folded into the category it is travel *for*, and appears as that category's "Travel related to …"
   sub-line. `1818` (security procedures while travelling) and `1899` (travel, nec) have nothing to
   fold into and land in "Other activities, not elsewhere classified".
2. **Two codes move house.** Household mail (`020903`) and e-mail (`020904`) are reported under
   "Telephone calls, mail, and e-mail", not under Household activities — which is why the published
   "Household management" line is smaller than tier 2 `0209`.
3. **Tier 1 = `10` splits, and it splits at tier *3*.** Government services (`1001`) go to
   "Purchasing goods and services"; civic obligations (`1002`) go to "Organizational, civic, and
   religious activities" — and so do **waiting for** (`100305`) and **travel to** (`181002`) a civic
   obligation, while the same two things for a government service (`100304`, `181001`) stay with
   Purchasing.

Point 3 is the one that cost real work. Every tier-2-level placement of `1003`, `1099`, `1809`,
`1810` and `1002` was enumerated — 243 combinations across all three years — and **none** reproduces
the table; the best left 17 cells wrong. Splitting the two civic codes at tier 3 takes the residual
from 17 to 2. Recorded because the next person will otherwise re-derive it: the convention is finer
than tier 2, and the two categories it moves between are the two smallest in the table
(0.67 and 0.30 hours a day), which is why nothing else in the table ever notices.

around; the exact number is not safe to print.

## Decisions that bind later stages

| # | Decided | Why | Rejected |
|---|---|---|---|
| E1 | The extract is **two files per year joined on `TUCASEID`** — `episodes-<year>.csv` and `respondents-<year>.csv` | 476k episode rows; denormalizing 26 demographic columns onto them quadruples the payload and adds nothing | A single denormalized table |
| E2 | The episode axis is **minutes since 4:00 a.m.**, 0–1439, stored as `START_MIN_FROM_4AM` | S2: it is the file's native axis, and it makes every day chain from 0 to exactly 1440 with no seam inside the data | Storing clock minutes and rotating later — it puts the truncation seam in the middle of the stored series |
| E3 | Age, sex, race, ethnicity, education and metro status are read **from the Activity Summary file's fixed-name columns**, never its `t######` columns | They exist on no other downloaded file; the S1 trap is specifically the minute columns, not the demographics | Downloading the Roster or ATUS-CPS file for demographics this project already has |
| E4 | Telework and commuting are **derived at bake time** into `WORK_AT_HOME_MIN` and `COMMUTE_MIN` | They exist only in the episode stream (`TEWHERE = 1` on tier 1 `05`; tier 2 `1805`); every consumer would otherwise re-derive them | A `TRTELWRK`-style respondent variable — there is none |
| E5 | The published-category map lives in `scripts/atus/categories.ts` and is **proven by the gate, not by naming** | The mapping is in no BLS document; 639 reproduced cells are the evidence | Assuming published majors are tier-1 codes — they are not, travel is redistributed |
| E6 | `data/raw/` and `data/extract/` stay **gitignored**; the pipeline plus the pinned hashes are the reproducible artifact | Byte-identical re-fetch is verified, so the extract is derivable, and 25 MB of derived CSV in git buys nothing | Committing the extract |
| E7 | The gate runs on every `npm run data` and **fails the build** on any mismatch outside the two pinned residuals | A silently-wrong extract is worse than none | Treating the gate as a one-time ticket-03 exercise |

## What this hands to the next tickets

- **Ticket 04 (render feasibility):** the payload floor is exact — 475,635 episodes over three years
  (182,980 + 153,120 + 139,535), 25,652 respondent-days, seven columns per episode, ~22 MB as raw
  CSV before any binning or quantisation. A minute-by-activity grid is 1440 × 12 majors per year,
  which is nothing; the cost only appears if the mark needs individual episodes.
- **Tickets 05/06 (spines):** the table above is the honest candidate list, and every number in it is
  now reproducible from source. The 4 a.m. seam (S2) and the no-simultaneity rule (S8) still bind
  what a time-of-day mark can assert.
- **Ticket 07 (freeze the claim):** S12 is live — any 2019-vs-2024 *change* needs the replicate
  weight files first. S8 and S9 remain the language constraints.
